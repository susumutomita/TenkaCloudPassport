# 調査室のスマホ画面

比較元は TenkaCloudChallenge `68b9fbe0d49f5f1d01e04cf8b52f284fd3153ee1` の
`battles/forensic-casebook/portal/StatusPanel.tsx` と `styles.ts`。
Cloud Master の画面とは別の、同じ問題・採点器の本体画面である。

## 利用者がたどる順序

事件を選び、記録を読み、結論と根拠をタップで選び、結果を確認して次へ進む。
本体の事件ごとのまとまり、得点、ログの見せ方、結論と根拠の階層を利用する。
スマホでは記録と回答を切り替え、十分な幅では並べて見られる。
最大文字では幅に関係なく一列にする。切り替えや幅の変化で回答は消さない。

1.5.1 に既にある問題名・タップ回答・正解反応・明示的な次へ操作は維持する。
選択中と解決済みは別に示す。内部の回答コードを日本語表示へ重ねて出さない。
問題ID、証拠の選択上限、正誤、得点、保存・再送の意味は変更しない。

参考記事の情報整理の考え方も用いるが、説明や装飾を足すことを目的にしない。
https://qiita.com/mskmiki/items/544149987475719e417b

## 検証の境界

比較画面は実際のコンポーネントと採点器を、隔離した架空データで表示したもの。
本番認証・実機・Simulator の確認とは区別する。
回帰では事件と問題番号の対応、選択中と解決済み、回答・根拠の切替保持、
狭幅から広幅への配置、保存失敗時の同一操作再送と再起動後の得点を確認する。
新しいネイティブモジュールや学習履歴の形式はこの変更に含めない。

適応型AI学習は、調査室と現在の暗号計算作問器の境界を明示した別の変更として扱う。
